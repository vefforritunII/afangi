## Markmið

Í þessu verkefni tileinkar þú þér **GitHub Flow**, létt og stöðugt vinnuflæði sem nýtist bæði í sjálfstæðum verkefnum og hjá fagfólki í atvinnulífinu. Markmiðið er að læra vinnubrögðin eingöngu í gegnum **Visual Studio Code**:

* Skilja og framfylgja reglum **GitHub Flow**.
* Stofna geymslusvæði (*repository*) og setja upp `.gitignore`.
* Skrá verkþætti með **GitHub Issues**.
* Vinna á lýsandi greinum (**feature branches**) sem kvíslast alltaf út frá nýjustu stöðu á `main`.
* Gera tíð og afmörkuð *commits*.
* Búa til, rýna breytingar (*diff*) og sameina **Pull Requests (PR)** beint í VS Code.
* Tengja PR við Issues þannig að þau lokist sjálfkrafa (`Closes #ID`).
* Leysa samrunaárekstur (**merge conflict**) með innbyggðum verkfærum í ritlinum.

---

### Hvað er GitHub Flow?

**GitHub Flow** byggir á fimm grundvallarreglum:

1. **Aðalgreinin (`main`) er alltaf tilbúin til birtingar:** Enginn vinnur beint á `main`.
2. **Kvíslun út frá `main`:** Þegar ný virkni eða lagfæring hefst er búin til ný grein með lýsandi heiti (t.d. `feature/issue-1-styling`).
3. **Regluleg commits:** Kóðinn er vistaður jafnt og þétt með skýrum lýsingum á greininni og sendur reglulega upp á GitHub (*Push*).
4. **Pull Request:** PR er opnað til að bera saman breytingarnar við `main`, fara yfir kóðann og rýna hann.
5. **Sameina (Merge) og eyða grein:** Þegar breytingarnar eru samþykktar eru þær sameinaðar inn á `main` og greininni eytt.

```text             
  main ──┬────────────────────────────────────────► Merge (PR) ──► main (alltaf virkt)
         │                                               ▲
         └─► [feature/grein] ──► Commit ──► Commit ──────┘
                                  (Push)     (Diff & Review)
```

---

### Undirbúningur 

1. **Uppsetning forrita:** Gakktu úr skugga um að [Git](https://git-scm.com/) og [Visual Studio Code](https://code.visualstudio.com/) séu uppsett á tölvunni.
2. **Viðbót í VS Code:**
    * Opnaðu Extensions flipann í VS Code (`Ctrl+Shift+X` eða `Cmd+Shift+X`).
    * Leitaðu að og settu upp: **GitHub Pull Requests** (opinber viðbót frá GitHub).
    * Skráðu þig inn á GitHub í gegnum VS Code þegar viðbótin biður um leyfi.

## Verkefnalýsing 

Þú ætlar að byggja einfalda vefsíðu (persónulega kynningarsíðu) í litlum skrefum samkvæmt GitHub Flow.

### Skref 1: Grunnur, `.gitignore` og upphafsstilling 

1. Búðu til nýja tóma möppu á tölvunni og opnaðu hana í VS Code.
2. Búðu til eftirfarandi skrár:
    * `index.html`: Einfaldur HTML5 grunnur með fyrirsögn og stuttum kynningartexta.
    * `README.md`: Titill verkefnisins og stutt lýsing á því um hvað síðan er.
    * `.gitignore`: Bættu við algengum kerfisskrám (t.d. `.DS_Store` og `Thumbs.db`).
3. Farðu í **Source Control** flipann í VS Code og smelltu á **Initialize Repository**.
4. Bættu öllum skrám við í stage (`+`), skrifaðu commit-skilaboðin `"feat: initial project setup and gitignore"` og smelltu á **Commit**.
   1. Ef þú þarft að setja inn user.name og user.email í git. Opnaðu Terminal > New Terminal.
      - git config --global user.name "YOUR_NAME"
      - git config --global user.email "YOUR_EMAIL"
5. Smelltu á **Publish Branch** í VS Code, veldu **Public Repository** og fylgdu leiðbeiningunum til að birta kóðann á aðganginum þínum.

---

### Skref 2: GitHub Flow í framkvæmd 1 – Útlit og stílar 

> [!IMPORTANT]
> **GitHub Flow regla:** Allt sem fer inn á `main` verður að koma í gegnum Pull Request. Eftir grunnuppsetningu er bannað að committa beint á `main`.

1. **Skrá Issue:** Farðu á GitHub eða í GitHub viðbótina í VS Code og stofnaðu Issue: `#1 Útbúa útlit og stíla fyrir vef`.
2. **Búa til grein af `main`:** Gakktu úr skugga um að þú sért á `main`. Búðu til nýja grein í stöðustikunni neðst í VS Code: `feature/styling`.
3. **Kóða og committa:**
    * Bættu við `style.css` og tengdu við `index.html`.
    * Útfærðu grunnútlit (letur, bakgrunnslit, bil og einfalt uppbrot).
    * Gerðu amk. tvö aðskilin commits í VS Code (t.d. `"feat: add reset and base typography"` og `"feat: add container layout styles"`).
    * Push-aðu greininni á GitHub (*Publish Branch*).
4. **Opna Pull Request í VS Code:**
    * Í **Source Control** eða **GitHub** flipanum í VS Code, smelltu á táknið fyrir **Create Pull Request**.
    * Í lýsingu á PR skrifar þú: `Closes #1`.
5. **Rýna og sameina (Merge):**
    * Rýndu eigin breytingar (*diff*) beint í ritlinum til að ganga úr skugga um að allt sé hreint.  
    * Smelltu á **Merge Pull Request** innan úr VS Code. Athugaðu að Issue #1 lokast sjálfkrafa.
6. **Hreinsa og uppfæra:**
    * Skiptu aftur yfir á `main` í VS Code og keyrðu **Pull** (eða *Sync Changes*).
    * Eyddu greininni `feature/styling` í VS Code.

> [!note]
> Alltaf að byrja á því að sækja af Github (pull and push) td. með að ýta á **Synchronize Changes** takka neðst í vinstra horni í VS Code.

---

### Skref 3: GitHub Flow í framkvæmd 2 – Gagnvirkt element

1. **Skrá Issue:** Búðu til Issue: `#2 Bæta við gagnvirkni (JavaScript)`.
2. **Kvísla af nýjustu `main`:** Gakktu úr skugga um að staðbundna `main` greinin sé uppfærð. Búðu til greinina `feature/interactivity`.
3. **Kóða og committa:**
    * Bættu við `main.js` og tengdu við síðuna.
    * Bættu við einfaldri virkni (t.d. hnappi sem skiptir á milli litaþema eða sýnir/felur texta).
    * Gerðu amk. tvö rökrétt commits á þessari grein og pússaðu henni á GitHub.
4. **PR, rýni og samruni:**
    * Opnaðu PR í gegnum VS Code með textanum `Closes #2`.
    * Farðu yfir breytingarnar og smelltu á **Merge Pull Request**.
    * Skiptu yfir á `main` í VS Code, taktu **Pull** og eyddu greininni `feature/interactivity`.


---

### Skref 4: Samrunaárekstur (Merge Conflict) leystur 

Stundum rekast breytingar á áður en hægt er að ljúka samruna. Hér æfir þú viðbrögð við því:

1. Búðu til nýja grein: `feature/footer-edit`.
2. Bættu við eða breyttu textanum í `<footer>` hluta `index.html`. Committaðu: `"feat: update footer copyright"`.
3. **Án þess að sameina greinina**, færðu þig aftur yfir á `main` í VS Code.
4. Breyttu **nákvæmlega sömu línu** í `<footer>` á `main` greininni í annan texta og committaðu: `"feat: change footer text on main"`.
5. Reyndu nú að sameina `feature/footer-edit` inn í `main` (t.d. með Command Palette `Ctrl+Shift+P` / `Cmd+Shift+P` -> `Git: Merge...` -> veldu `feature/footer-edit`).
6. Git mun stöðva samrunann og tilkynna árekstur.
7. Opnaðu skrána og smelltu á **Resolve in Merge Editor** í VS Code. Veldu hvaða breyting á að gilda (eða sameinaðu handvirkt), smelltu á **Complete Merge**, committaðu lausninni og sendu upp á GitHub (*Push*).

## Skil á verkefni

Skila skal hlekk á GitHub geymslusvæðið (*repository*) í gegnum Canvas.

**Kröfur um skil:**

* [ ] Skráin `.gitignore` er til staðar í rót verkefnis.
* [ ] Að minnsta kosti 2 lokuð **Issues** undir flipanum *Issues*.
* [ ] Að minnsta kosti 2 samþykkt og sameinuð **Pull Requests** sem tengjast viðkomandi Issues (`Closes #ID`).
* [ ] Aðferðafræði **GitHub Flow** sýnileg í sögunni (unnið á greinum, regluleg commits, breytingar sameinaðar í gegnum PR).
* [ ] Kóðasaga á `main` sýnir að samrunaárekstur hafi verið leystur.
